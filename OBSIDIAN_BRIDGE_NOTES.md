# Obsidian bridge

## Что добавлено

### 1. Автогенерируемая очередь внутри vault
Приложение теперь создаёт и обновляет файл:

- `_SRS Queue.md`

В нём есть:
- сводка по текущей нагрузке,
- блок **«Минимум на сегодня»**,
- блок **«Сессия на 30 минут»**,
- блок **«Сегодня в фокусе»**,
- полная очередь заметок по срочности,
- список новых заметок без review-истории,
- результаты последней обработки команд.

Это позволяет использовать Obsidian как основной интерфейс для планирования повторений без отдельной Android-сборки.

### 2. Командный файл внутри vault
Приложение теперь создаёт и отслеживает файл:

- `_SRS Commands.md`

Нужно писать команды только между маркерами:

```md
<!-- SRS-COMMANDS:START -->
обновить
review 7 [[folder/note]]
<!-- SRS-COMMANDS:END -->
```

Когда приложение видит команды, оно:
1. выполняет их по очереди,
2. пишет результат в лог и в `_SRS Queue.md`,
3. очищает секцию команд.

## Поддерживаемые команды

- `обновить` / `update`
- `сканировать` / `scan`
- `синхронизировать` / `sync`
- `отчёт` / `report`
- `очередь` / `queue`
- `ревью 7 [[folder/note]]`
- `review [[folder/note]] 7`

## Как этим пользоваться

### Базовый сценарий
1. Открыть приложение и выбрать vault.
2. Держать приложение открытым.
3. Работать в Obsidian.
4. Смотреть очередь в `_SRS Queue.md`.
5. Когда нужно пересчитать всё или добавить review — писать команду в `_SRS Commands.md`.

### Самый удобный цикл учёбы
1. Открыть `_SRS Queue.md`.
2. Взять заметки из блока **«Минимум на сегодня»** или **«Сегодня в фокусе»**.
3. После прохождения заметки отправить команду `review ...` или `обновить`.
4. Снова вернуться в очередь.

## Что это даёт по продуктивности

- меньше переключений между GUI и Obsidian,
- меньше ручного выбора следующей заметки,
- меньше риска забыть новые заметки без initial review,
- более естественный рабочий поток через markdown-файлы,
- простой мост к будущему плагину.

## Что уже подготовлено под будущий плагин

Сейчас логика разнесена так, что переносить удобнее:
- `srs.py` содержит ядро расчётов, очереди и команд,
- `gui.py` выступает как оболочка,
- Obsidian-файлы уже используются как внешний интерфейс.

Это хороший промежуточный слой: следующий шаг — переписать ядро на TypeScript и подключить его как Obsidian-плагин.
