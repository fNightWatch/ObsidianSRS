# Plugin port evaluation

## Короткая оценка
Перенос в Obsidian-плагин выглядит как **средняя сложность**.

Не потому, что логика тяжёлая, а потому что:
- текущее ядро написано на Python,
- Obsidian-плагин придётся писать на TypeScript,
- UI нужно будет собирать через Obsidian API, а не через tkinter.

## Что уже облегчает перенос

Сейчас проект уже ближе к архитектуре плагина, чем раньше:
- расчёт срочности и сбор очереди собраны в одном месте,
- работа через markdown-файлы внутри vault уже есть,
- GUI можно считать отдельной оболочкой, а не центром системы.

Это значит, что перенос идёт не по схеме «переписать всё», а по схеме:
1. переписать ядро `srs.py` на TypeScript,
2. заменить операции с файлами на Obsidian API,
3. сначала оставить те же `_SRS Queue.md` и `_SRS Commands.md`,
4. потом добавить нативный view/settings/commands.

## Самый реалистичный путь переноса

### Этап 1. Минимальный плагин
Плагин делает только это:
- пересчитывает очередь,
- обновляет `_SRS Queue.md`,
- обрабатывает `_SRS Commands.md`,
- даёт несколько команд в command palette.

Это самый дешёвый по времени путь.

### Этап 2. Нативный интерфейс внутри Obsidian
Потом можно добавить:
- отдельный view с очередью,
- быстрые кнопки review,
- фильтры по band/папкам,
- настройки путей и лимитов,
- режим учебной сессии.

### Этап 3. Мобильная совместимость
После desktop-first версии можно отдельно довести мобильные ограничения.

## Моя практическая оценка

### Что переносится легко
- формула urgency,
- band-логика,
- генерация markdown-очереди,
- синтаксис командного файла,
- работа с относительными путями заметок.

### Что переносится средней ценой
- фильтры и сортировки отчёта,
- preview заметок,
- state/settings,
- фоновое отслеживание команд.

### Что переносится сложнее
- весь текущий tkinter UI как есть,
- поведение, завязанное на desktop-only привычки,
- тонкая поддержка mobile-first UX.

## Вывод
Лучший следующий шаг — не пытаться перенести текущий GUI целиком, а сделать **плагин-ядро с тем же файловым workflow**.

То есть сначала оставить интерфейс через:
- `_SRS Queue.md`
- `_SRS Commands.md`

А уже потом заменить этот мост на полноценный нативный интерфейс внутри Obsidian.
